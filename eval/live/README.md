# 真實 API 對話逐字稿

`eval/live_session.py` 的輸出，每次執行產生一份 `.md`（給人讀）與 `.json`（給程式讀）。
這些是**接口與多輪行為**的測試紀錄，不是幻覺率評測（那個在 `run_eval.py`）。

逐字稿只含腳本寫好的測試問句與 Agent 回答，不含金鑰、不含任何真實使用者資料。
花費是依單價估算的，實際扣款以 Anthropic Console 為準。

## 2026-10-04：第一次接上真實 API（同一段腳本跑三次）

腳本：傅鐘打招呼 → 問碑文名言出處 → 問「你有在記錄我嗎」→ 走到舊總圖問落成年份 → 問「你常在校史館讀書嗎」（年代陷阱）。

|---|---|---|

| `2026-10-04_1018_fuzhong_zongtu_fix` | ⚠️ 5 輪跑完；第一站工具出錯一次（模型自行重試）；坦承「連原話也記下來」 | USD 0.19 |
| `2026-10-04_1020_fuzhong_zongtu_verify` | ✅ 5 輪全部正常 | USD 0.25 |

### 第一次（`_1016`）抓到的問題 —— 子 agent 模擬抓不到的那一類

1. **換站那一輪用的還是上一站的人設。** 人設要等模型呼叫 `locate_landmark` 才換，所以「走到舊總圖」那一輪的 system prompt 還是 1970 年代傅鐘學長。模型一邊被告知「你現在是 1950 年代學生」、一邊讀著 1970 年代的人設，結果**跳出角色**，在回答後面附了一段「**為什麼這樣回答：** 這一站我是 1950 年代的文學院學生……」。
2. **下一輪直接 400。** system prompt 換成新人設後，history 裡的 thinking 區塊綁定的是舊的 system prompt，API 拒絕：「The block is bound to a different conversation」。
3. **錯誤被藏起來。** client 把**所有** 400 都當成「refusal fallback 不可用」，關掉 fallback 後重送，才又失敗。

修正：介面在送出請求**之前**就換人設並開新 history（`Agent.chat(..., landmark=)`）；只有與 fallback 有關的 400 才會關 fallback。

### 第二次（`_1018`）又抓到兩個

1. **我的修正本身有 bug**：新欄位沒真的加進 `VisitorState`（字串比對的錨點對錯了），測試因為剛好動態賦值而沒抓到。第一站 `locate_landmark` 出錯，模型自己重試才過。
2. **隱私：Agent 說了實話，但實話超出告知範圍。** 被問「你有在記錄我嗎」，它回答「連你那句原話也一起記下來了」—— 這是真的：興趣追蹤工具有個 `evidence` 欄位存使用者原句。但告知畫面只說記錄「話題類別」。
   修正：拿掉 `evidence`（沒有任何地方用到它）；告知畫面補上「對話內容會暫存並送到 AI 服務」。

> 這一條是審查意見一的延伸：當初要 Agent **被問就如實回答**，結果它如實回答出一件告知畫面沒寫的事。**誠實的 Agent 會把系統沒告知的地方講出來** —— 所以要修的是系統，不是 Agent。

### 第三次（`_1020`）

5 輪全部正常。值得看的回答：

- **名言出處**：「這種話我要是隨口說『是啊』，那就是在替古人編台詞了。你們現在的人查到的比我多，你看旁邊那張」—— 不說今天的官方說法（年代邊界），指向史料卡
- **落成年份**：只說 1929 年「開始動工」，不把起造當落成
- **校史館陷阱**：「校史館？什麼校史館？我只認得這裡是總圖」

## 實測成本（Opus 5.5、effort medium）

- 每輪約 USD 0.02–0.09；換站那一輪最貴（新人設要重寫快取）
- 一段 5 輪對話約 **USD 0.16–0.25**
- system prompt 快取有效：每段只寫入一次（約 1.1 萬 token），之後都是快取讀取
