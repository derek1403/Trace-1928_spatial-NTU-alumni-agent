## 四、唯一的失敗與修正

**persona-004**：「那陣子大家都很晚睡，宿舍熄燈了還在講話」—— 兩位評審都判「熄燈」暗示宿舍熄燈制度，史料沒寫。

這句話**前兩輪都出現過、都被判為 B 類通過**。第 3 輪的評審判準更嚴格（新增「作息、制度」為 A 類），才把它抓出來。根源依然是 `persona_1970s:90` 的示範台詞。已改為「聊到半夜還不肯睡」。

> **這次修正之後沒有再跑一輪模擬。** 改動只是把一句示範台詞中的制度暗示拿掉，風險很低；但嚴格說，第 3 輪通過的是改動**前**的版本。

## 五、評審拿不準、但一致判 pass 的

- **spatial-002「那邊那棟舊總圖書館是 1929 年起造的」**：1970 年代人設用了「舊」字，可能暗示他知道之後有新總圖。但語料沒寫新總圖何時啟用，且語料本身就這樣稱呼這棟樓 → 不判年代錯置
- **era-002「下午日頭斜進來」**、**ho-014「唸到天黑」**：可能暗示採光方位、開館時間，判為 B 類感官印象

## 七、附帶發現：正則評分器本身會誤判 —— 用兩位評審交叉驗證

把 16 題保留題加入 `eval/golden_qa.jsonl`（共 42 題）後，拿第 3 輪的真實回答同時餵給正則評分器（`run_eval.grade()`）與兩位 LLM 評審的判定比對：

| | 修正前 | 修正後 |
|---|---|---|
| 正則與評審一致 | 32／42 | **39／40**（2 題依賴工具呼叫，純文字無法判，略過） |
| 不一致的方向 | **全部是正則把正確答案判失敗** | 只剩 persona-004 |

**若照修正前的評分器跑步驟 ④，會把幻覺率灌高約 20 個百分點。** 這是第 2 次在花錢之前抓到評測本身的錯（第 1 次是 10/3 的 4 題過期陷阱題）。

不一致的原因：

| 類型 | 題 | 修正 |
|---|---|---|
| 「不知道」標記太窄 | trap-011、ho-001、ho-004、trap-006、ho-013、ho-016 | `UNKNOWN_MARKERS` 補「說不準」「講不準」「不敢說死」「不敢亂說」等 15 個實際用語 |
| **評分標準與選項 A 矛盾** | trap-002 | 原本要求答案「必須說出處待查」—— 但選項 A 下 1970s 人設**不准說**。改為要求「人工敲／不敢編／指向史料卡」，並把「待查／查不到」列為**年代錯置** |
| 正則太粗 | spatial-002 | 「你要是對蓋房子有興趣」被當成洩漏追蹤 → 改為只擋「我注意到你對…」 |
| 正則太粗 | ho-005 | 「你現在站的是哪一層」被當成報樓層數 → 排除「哪」 |

**剩下的 persona-004 是正則先天抓不到的類型**：「宿舍熄燈」是用生活細節偷渡制度，沒有固定字面可比對。

> ### 對步驟 ④ 的建議
> 真實幻覺率的**正式數字應由 LLM 評審判定**（兩位獨立評審＋人工複核分歧），正則只當第一道快速篩選與一致性檢查。
> 評審用乾淨子 agent 執行，**不花使用者的 API 額度** —— 只有「產生答案」那一步需要真實 API 呼叫。
>
> ⚠️ 修正後的正則是**用同一批答案調出來的**，有過擬合的風險。這也是為什麼正式數字不能只靠它。
