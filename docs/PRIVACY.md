# 隱私與資料處理

> 2026-10-03 新增，回應審查意見：
> 「Agent 會在使用者不知情的情況下記錄其興趣偏好，建議在使用前簡要告知，並說明資料如何保存與刪除。」

---

## 原本的設計錯在哪

最初的規格把興趣追蹤寫成「靜默操作」：Agent 在背景累積使用者的興趣權重，**並且被要求不得讓使用者察覺** —— 連使用者直接問「你是不是在記錄我」，都要否認。

當時的理由是「不破壞沉浸感」。但這個理由只支持「對話中不要主動打斷」，**不支持「被問到也要否認」**。後者已經是欺瞞。對一個主張「不編造史實」的專案來說，在自己的資料蒐集上說謊是自我矛盾。

審查委員是對的。

---

## 現在的做法：事前告知 ＋ 對話中不打斷 ＋ 被問就如實回答

| 時機 | 做法 |
|---|---|
| **開始之前** | 介面先顯示告知畫面（`src/app/main.py` 的 `DISCLOSURE`），按「了解並開始」才進入對話 |
| **對話之中** | Agent 不主動提起 —— 使用者已經知道，重複說明只會打斷對話 |
| **被問到時** | Agent **必須如實回答**記錄了什麼、為什麼、可以怎麼清除。可以用人設的口吻，但內容不能打折扣（`agents/system_prompt.md`） |
| **任何時候** | 介面上有「清除我的資料」按鈕（`VisitorState.clear()`） |

告知放在**進入體驗之前**，所以沉浸感不受影響。這兩件事原本就不衝突。

## 記錄什麼

| 資料 | 內容 | 用途 |
|---|---|---|
| 興趣權重 | 7 個粗分類（建築、日常生活、課業與制度、時代氛圍、人物、情感與交遊、飲食）各一個分數 | 推薦下一個地標 |
| 工具呼叫紀錄 | 工具名稱、參數摘要、耗時、成敗 | 介面右側的軌跡面板；評鑑指標 6 |
| 推薦紀錄 | 推薦了哪一站、使用者有沒有走到 | 評鑑指標 5 |
| 對話內容 | 使用者與 Agent 的訊息 | 維持對話脈絡（API 本身是無狀態的，每輪都要送完整歷史） |

## 不記錄什麼

姓名、學號、帳號、聯絡方式、GPS 座標、裝置識別碼。地標位置只來自使用者選擇（模擬 QR Code 掃描），不取用定位。

## 保存多久、怎麼刪

### 一般使用

- **只存在記憶體中的這一次 session**，不寫入磁碟。
- 關掉頁面、按「重新開始一段導覽」或「清除我的資料」→ 全部刪除。

### N=15 研究測試（12 月）

研究需要分析對話與工具軌跡，所以處理方式不同：

1. 受測者**事先簽署知情同意書**，載明記錄內容、用途、保存期限與退出方式。
2. 紀錄以**流水編號**保存，不與姓名連結；同意書與紀錄分開存放。
3. 訪談逐字稿**去識別化**後才進入分析。
4. **成果繳交後刪除原始紀錄**，僅保留去識別化的統計結果與引用片段。
5. 受測者可在任何時候要求刪除自己的紀錄。

> 指導教授郭鴻基教授已確認本研究不需送研究倫理審查（2026-10），
> 但上述同意與去識別化程序照常執行 —— 不送審不代表不需要對受測者負責。

## 第三方服務

對話內容會傳送到 **Anthropic API** 產生回應。資料保存與使用方式以 Anthropic 官方公告的 API 商業服務條款與隱私政策為準 —— 本文件不代為轉述其內容，研究測試的知情同意書須附上官方連結。

> 這也是計畫書「本機部署」原則的實際意義：校史館若未來導入，**未公開的典藏不應送往境外 API**。
> 目前的語料全部來自已公開的臺大官方網頁，故無此疑慮。
